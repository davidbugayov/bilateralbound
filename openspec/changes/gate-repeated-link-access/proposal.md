# Gate Repeated Link Access

## Why

Постоянные ссылки (`/c/:id`, `/s/:id`) создаются только при активной подписке, но после создания работают вечно и бесплатно для любого браузера: подписка проверяется один раз в `reserve`, а дальше доступ не ограничен ничем. Это обесценивает подписку (75⭐/30 дней) — ссылку сохраняют и пользуются ей бесконечно без оплаты. Нужно: первый вход по ссылке с браузера бесплатный, повторный вход с того же браузера — paywall с проверкой подписки через Telegram ID.

## What Changes

- **Первый вход по ссылке** (`/c/:sessionId`, `/s/:sessionId`) — бесплатный: сервер выдаёт браузеру cookie-метку (anonymous id), доступ открыт.
- **Повторный вход** с того же браузера — вместо HTML страницы отдаётся paywall: кнопка на бота @emdrbilateral_bot (75⭐) + поле ввода Telegram User ID для проверки подписки.
- **Проверка подписки** при повторном входе: сервер проверяет `subscriptionService.isActive(telegramUserId)`; при успехе — доступ открыт и метка «оплачено» закрепляется за браузером (cookie), чтобы не спрашивать в течение срока подписки.
- **Ограничение действует на оба типа страниц**: controller (`/c/`) и viewer (`/s/`).
- **Подписанный пользователь** (владелец ссылки, у которого активна подписка по этому customId) — повторные входы без paywall: проверка по владельцу ссылки пропускает paywall.
- **BREAKING**: меняется поведение GET `/c/:sessionId` и GET `/s/:sessionId` — при повторном входе без подписки вместо контента отдаётся paywall. Новый эндпоинт проверки подписки (или переиспользование `activate-by-telegram`) для разблокировки.

## Capabilities

### New Capabilities

- `link-access-gating`: ограничение повторного доступа к постоянным ссылкам (`/c/`, `/s/`) по cookie-метке браузера и проверка подписки при повторном входе.

### Modified Capabilities

## Impact

- **Server** (`packages/server-core`):
  - `static_routes_controller.js` — GET `/c/:sessionId`, `/s/:sessionId`: логика первого/повторного входа, paywall-ответ.
  - `subscriptionController.js` — переиспользование/расширение `activate-by-telegram` для разблокировки браузера; возможно новый эндпоинт `GET /api/link-access/:sessionId` для проверки статуса.
  - Новый модуль (например, `AccessGatingService` или функция в `network/`): cookie-метки, хранение «уже видели / оплачено», связка с `SubscriptionService`.
  - Middleware: установка cookie на первый вход (учесть `sameSite`, `secure`, CSRF-схему).
- **Client** (`packages/web-client`):
  - Новый paywall-экран (HTML/JS) для viewer и controller при блокировке.
  - Логика «проверить статус → показать контент или paywall → ввод Telegram ID → разблокировка».
  - i18n: новые строки для paywall (все 8 языков), через существующий single-source механизм.
- **Сервис-воркер**: проверить, не кэширует ли он HTML страниц `/c/` и `/s/` (нужны no-cache и корректная обработка paywall).
- **Данные**: cookie без логина — компромисс «удалить cookie = снова бесплатно»; это осознанное ограничение, фиксируется в дизайне.
