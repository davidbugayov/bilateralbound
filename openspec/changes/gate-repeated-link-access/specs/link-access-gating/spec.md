## Purpose

Ограничивает повторный доступ к постоянным ссылкам сессий (`/c/:sessionId`, `/s/:sessionId`): первый вход с браузера бесплатный, повторный — требует активную подписку (75⭐), чтобы монетизировать бессрочно сохраняемые ссылки.

## ADDED Requirements

### Requirement: Первый вход по ссылке бесплатный

Система MUST разрешать первый вход по постоянной ссылке (`/c/:sessionId` или `/s/:sessionId`) с любого браузера без проверки подписки. При первом входе система MUST выдать браузеру cookie-метку, однозначно идентифицирующую этот браузер для данной ссылки.

#### Scenario: Новый браузер открывает ссылку впервые
- **WHEN** браузер без cookie-метки запрашивает GET `/c/:sessionId` (или `/s/:sessionId`)
- **THEN** система отдаёт полную страницу (controller/viewer HTML) и устанавливает cookie-метку в ответе

#### Scenario: Один бесплатный доступ на ссылку, а не на тип страницы
- **WHEN** браузер, уже получивший cookie-метку на `/c/:sessionId`, запрашивает `/s/:sessionId` для той же ссылки
- **THEN** система считает это повторным входом для данной ссылки (controller и viewer — одна ссылка) и без подписки возвращает paywall-страницу

### Requirement: Повторный вход без подписки блокируется

При повторном запросе той же ссылки с браузера, уже имеющего cookie-метку, система MUST НЕ отдавать контент страницы, а вернуть paywall-страницу с предложением поддержать проект и проверить подписку, пока для браузера не подтверждена активная подписка.

#### Scenario: Повторный запрос с тем же браузером без подписки
- **WHEN** браузер с cookie-меткой повторно запрашивает GET `/c/:sessionId`, и для этого браузера не подтверждена активная подписка
- **THEN** система возвращает paywall-страницу (не HTML controller) с кнопкой на бота и формой ввода Telegram User ID

#### Scenario: Повторный запрос viewer без подписки
- **WHEN** браузер с cookie-меткой повторно запрашивает GET `/s/:sessionId` без активной подписки
- **THEN** система возвращает paywall-страницу вместо HTML viewer

### Requirement: Проверка подписки по Telegram User ID

Paywall-страница MUST содержать форму ввода Telegram User ID. Система MUST проверять активность подписки для введённого ID через существующий механизм подписки (`isActive(telegramUserId)`). При успешной проверке система MUST открыть доступ и закрепить статус «оплачено» за браузером.

#### Scenario: Ввод ID с активной подпиской
- **WHEN** пользователь на paywall-странице вводит Telegram User ID, для которого есть активная подписка, и отправляет форму
- **THEN** система подтверждает подписку, открывает доступ к странице и запоминает статус оплаты для браузера

#### Scenario: Ввод ID без активной подписки
- **WHEN** пользователь вводит Telegram User ID без активной подписки
- **THEN** система сообщает об ошибке и остаётся на paywall-странице

#### Scenario: Некорректный формат ID
- **WHEN** пользователь вводит нечисловой или пустой Telegram User ID
- **THEN** система отклоняет ввод с сообщением об ошибке без обращения к проверке подписки

### Requirement: Пропуск paywall для владельца ссылки

Если для ссылки (sessionId) уже связана активная подписка через `customId` (владелец ссылки — подписанный пользователь), система MUST пропускать paywall при повторном входе — проверка по владельцу ссылки имеет приоритет над cookie-меткой.

#### Scenario: Владелец ссылки с активной подпиской заходит повторно
- **WHEN** браузер с cookie-меткой повторно запрашивает `/c/:sessionId`, и для этого sessionId в системе есть активная подписка владельца
- **THEN** система отдаёт полную страницу без paywall

#### Scenario: Владелец ссылки без активной подписки заходит повторно
- **WHEN** браузер с cookie-меткой повторно запрашивает ссылку, и подписка владельца этого sessionId истекла или отсутствует
- **THEN** система блокирует доступ paywall-страницей (без исключений)

### Requirement: Разблокировка действует до истечения подписки

После успешной проверки подписки для браузера статус «оплачено» MUST действовать до истечения срока подписки, после чего повторный вход снова блокируется paywall, пока подписка не будет продлена.

#### Scenario: Повторный вход в течение срока подписки
- **WHEN** браузер с подтверждённой подпиской запрашивает ссылку до истечения срока
- **THEN** система отдаёт полную страницу без paywall

#### Scenario: Повторный вход после истечения подписки
- **WHEN** браузер с подтверждённой ранее подпиской запрашивает ссылку после истечения срока
- **THEN** система снова возвращает paywall-страницу

### Requirement: Paywall-строки локализованы

Все тексты paywall-страницы (заголовок, описание, кнопка на бота, подписи формы, сообщения об ошибках) MUST быть реализованы через i18n-механизм проекта (все 8 языков), без хардкода строк в HTML/JS.

#### Scenario: Отображение paywall на русском
- **WHEN** пользователь с русским языком видит paywall-страницу
- **THEN** все тексты paywall отображаются на русском из i18n-строк

#### Scenario: Отображение paywall на другом языке
- **WHEN** пользователь с языком, отличным от русского (например, японским), видит paywall-страницу
- **THEN** все тексты paywall отображаются на выбранном языке из i18n-строк

### Requirement: Не-существующая сессия не блокируется

Для несуществующей сессии (sessionId, отсутствующий в хранилище сессий) система MUST сохранять текущее поведение (404 или страница с ошибкой) и не выдавать cookie-метку доступа.

#### Scenario: Запрос ссылки несуществующей сессии
- **WHEN** браузер запрашивает `/c/:несуществующийId`
- **THEN** система возвращает ответ как и раньше (не paywall), без установки cookie-метки
