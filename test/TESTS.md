# ✅ План тестирования BilateralBound

Этот документ описывает все тест-кейсы для проекта, их статус и то, как они покрываются автоматизированными тестами.

## 🗂️ Архитектура тестирования

Текущая архитектура тестирования состоит из двух основных файлов, находящихся в директории `test/`:

1.  **`automated-tests.js`** — Автоматизированные тесты серверной логики, API и WebSocket. Запускаются через Node.js.
2.  **`ui-tests.js`** — End-to-end тесты пользовательского интерфейса. Используют Puppeteer для автоматизации действий в браузере.

### 🚀 Запуск тестов

```bash
# Запуск серверных и API тестов
node test/automated-tests.js

# Запуск UI тестов (требует запущенного сервера)
node test/ui-tests.js
```

## 💡 Идеи для будущих тестов

- **Полное покрытие граничных условий:** Автоматизировать тесты для некорректных, нулевых и максимальных значений.
- **Тесты безопасности:** Добавить тесты на валидацию ввода (SQL-инъекции, XSS), а также проверить CORS и rate limiting.
- **Тесты на отказ и восстановление:** Автоматизировать сценарии с потерей сети и "штормом" переподключений.
- **Нагрузочные тесты:** Использовать инструменты, такие как `k6` или `Artillery`, для симуляции высокой нагрузки на WebSocket и API.
- **Мобильное тестирование:** Настроить Appium или аналогичный фреймворк для автоматизации тестов на мобильных устройствах.
