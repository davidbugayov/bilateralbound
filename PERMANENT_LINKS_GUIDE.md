# 🔗 Руководство по постоянным ссылкам

## Обзор

Система постоянных ссылок позволяет создавать персональные URL-адреса для каждого клиента, которые остаются действительными навсегда. Больше не нужно каждый раз генерировать новые ссылки для каждой сессии.

## ✨ Основные преимущества

1. **Постоянство** - Ссылки создаются один раз и работают всегда
2. **Удобство** - Не нужно генерировать новые ссылки перед каждой сессией
3. **Организация** - Каждый клиент получает свой уникальный идентификатор
4. **Простота** - Интуитивный интерфейс на главной странице

## 🎯 Как использовать

### Через веб-интерфейс (Рекомендуется)

1. Откройте главную страницу приложения
2. Найдите раздел **"🔗 Постоянные ссылки для клиентов"**
3. Введите ID клиента (например: `anna_2025`, `client_ivan`, `session42`)
4. Нажмите **"🔗 Создать ссылки"**
5. Система сгенерирует две ссылки:
   - **👁️ Ссылка для клиента (Viewer)** - отправьте эту ссылку клиенту
   - **🎮 Ссылка для терапевта (Controller)** - откройте эту ссылку сами
6. Используйте кнопки **"📋 Копировать"** для быстрого копирования ссылок

### Через API

```bash
POST /api/session/{clientId}/reserve
```

**Пример запроса:**
```bash
curl -X POST http://localhost:3000/api/session/anna_2025/reserve \
  -H "Content-Type: application/json"
```

**Пример ответа:**
```json
{
  "sessionId": "anna_2025",
  "viewerUrl": "http://localhost:3000/s/anna_2025",
  "controllerUrl": "http://localhost:3000/c/anna_2025"
}
```

## 📝 Правила для ID клиента

ID клиента должен соответствовать следующим требованиям:

- **Длина:** от 3 до 32 символов
- **Разрешенные символы:** 
  - Латинские буквы (A-Z, a-z)
  - Цифры (0-9)
  - Подчеркивание (_)
  - Дефис (-)
- **Примеры правильных ID:**
  - `anna_2025`
  - `client-ivan`
  - `session42`
  - `maria_therapy`
  - `test_client_001`

## 🔄 Сценарии использования

### Сценарий 1: Работа с одним постоянным клиентом

1. Создайте ссылки для клиента один раз (например, ID: `anna_2025`)
2. Сохраните обе ссылки в закладках браузера или заметках
3. Перед каждой сессией:
   - Отправьте клиенту ссылку viewer (если она ещё не у него)
   - Откройте свою ссылку controller
4. Всё готово к работе!

### Сценарий 2: Управление несколькими клиентами

1. Создайте уникальный ID для каждого клиента:
   - `client_anna`
   - `client_ivan`
   - `client_maria`
2. Сгенерируйте ссылки для каждого
3. Сохраните их в таблице или CRM-системе:
   ```
   Клиент     | Viewer URL                          | Controller URL
   -----------|-------------------------------------|-------------------------------------
   Анна       | https://...online/s/client_anna     | https://...online/c/client_anna
   Иван       | https://...online/s/client_ivan     | https://...online/c/client_ivan
   Мария      | https://...online/s/client_maria    | https://...online/c/client_maria
   ```
4. Перед сессией просто откройте нужную controller-ссылку

## 🎨 Интерфейс

### Валидация в реальном времени

Система автоматически проверяет корректность введенного ID:
- ✅ **Зелёный цвет** - ID корректен
- ⚠️ **Оранжевый цвет** - есть ошибки в формате
- ❌ **Красный цвет** - критическая ошибка

### Копирование в буфер обмена

Каждая сгенерированная ссылка имеет кнопку **"📋 Копировать"**:
- Один клик - ссылка скопирована
- Показывается уведомление об успешном копировании
- Работает во всех современных браузерах

### Светлая/Тёмная тема

Интерфейс автоматически адаптируется к выбранной теме:
- Контрастные цвета для лучшей читаемости
- Плавные переходы между темами
- Сохранение предпочтений пользователя

## 🔧 Технические детали

### Автоматическое создание сессий

При подключении по постоянной ссылке:
1. Если сессия с таким ID уже существует - используется существующая
2. Если сессия не существует - создается новая автоматически
3. Если старая сессия была удалена - создается заново с тем же ID

### Идемпотентность

Можно многократно вызывать API резервирования с одним и тем же ID:
- Первый вызов создает сессию
- Последующие вызовы возвращают информацию о существующей сессии
- Ссылки всегда остаются одинаковыми

### Очистка сессий

Система автоматически очищает неактивные сессии:
- Сессии старше 1 часа
- Сессии без активности более 30 минут
- Но ID остается доступным для повторного использования


## 💡 Советы и рекомендации

1. **Именование ID:** Используйте понятные имена, например: `client_anna_therapy_2025`
2. **Безопасность:** ID не должен содержать личную информацию (только имя или псевдоним)
3. **Организация:** Ведите список всех созданных ID и их владельцев
4. **Закладки:** Создавайте папки с закладками для разных клиентов
5. **Тестирование:** Протестируйте ссылки сразу после создания

## ❓ FAQ

**Q: Можно ли изменить ID после создания?**
A: Нет, ID постоянный. Но можно создать новый ID и использовать его.

**Q: Что если я потеряю ссылки?**
A: Можно заново вызвать API с тем же ID - вернутся те же ссылки.

**Q: Сколько клиентов можно создать?**
A: Практически неограниченное количество (технический лимит ~10 миллионов).

**Q: Работают ли старые одноразовые ссылки?**
A: Да, старая система продолжает работать параллельно.

**Q: Можно ли удалить постоянную ссылку?**
A: ID нельзя удалить, но неактивные сессии автоматически очищаются.
