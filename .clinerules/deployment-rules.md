# Правила деплоя для AI ассистентов

## ⚠️ КРИТИЧЕСКИ ВАЖНО: Стратегия деплоя

### Автоматический деплой (через webhook)
- **Когда:** При push в GitHub (ветка stable или main)
- **Что делает:** Автоматически обновляет код, устанавливает зависимости и перезапускает сервис
- **Файлы:** webhook-server.js обрабатывает push события

### Ручной деплой (manual-deploy.sh)
- **Когда:** Только если автоматический деплой не сработал
- **Что делает:** 
  - Проверяет существующие директории
  - Если директория существует → `git pull` (обновление по коммиту)
  - Если директории нет → `git clone` (полная установка)
  - НЕ ДЕЛАЕТ полную переустановку если директория уже существует

## 🚫 ЗАПРЕЩЕНО делать:

1. **НЕ удалять существующие директории** перед деплоем
   - `/var/www/bilateralbound-prod`
   - `/var/www/bilateralbound-prod-ru`
   - `/var/www/bilateralbound-dev`

2. **НЕ делать полную переустановку** если webhook сработал корректно

3. **НЕ клонировать репозиторий заново** если директория уже существует

## ✅ ПРАВИЛЬНЫЙ процесс:

### 1. При обычных изменениях:
```bash
# Просто push - webhook сделает всё автоматически
git add .
git commit -m "описание изменений"
git push origin stable  # или main для dev
```

### 2. Если webhook НЕ сработал:
```bash
# Используйте manual-deploy.sh - он делает git pull
./manual-deploy.sh
# Выберите нужное окружение
```

### 3. Только в экстренных случаях (проблемы с Git):
```bash
# Удалить директорию и переустановить
ssh root@213.139.229.44 "rm -rf /var/www/bilateralbound-prod"
./manual-deploy.sh  # Теперь сделает git clone
```

## 📊 Проверка статуса деплоя

```bash
# Проверить логи webhook
ssh root@213.139.229.44 "tail -100 /var/log/webhook-deploy.log"

# Проверить статус сервисов
ssh root@213.139.229.44 "systemctl status bilateralbound-prod bilateralbound-prod-ru bilateralbound-dev"

# Проверить последний коммит на сервере
ssh root@213.139.229.44 "cd /var/www/bilateralbound-prod && git log -1 --oneline"
```

## 🎯 Workflow для AI ассистента:

1. **Перед любыми действиями:**
   - Проверить логи webhook - возможно деплой уже произошел
   - Проверить текущий коммит на сервере
   
2. **Если нужен ручной деплой:**
   - НЕ удалять существующие директории
   - Использовать `./manual-deploy.sh` как есть
   - Скрипт сам решит что делать (pull или clone)

3. **После деплоя:**
   - Проверить статус сервисов
   - Проверить логи приложений
   - Убедиться что нужный коммит развернут
