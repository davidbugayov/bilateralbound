## Bilateral Bound (EMDR)

**🎯 ВАЖНО:** Перед каждым коммитом запускайте тесты! `http://localhost:3000/test/test-system.html`

Интерактивный инструмент двусторонней стимуляции (EMDR) с управлением движущимся объектом (шаром) в реальном времени через веб‑сокеты. Проект состоит из:

- фронтенда на GitHub Pages: [страница создания сессии](https://davidbugayov.github.io/bilateralbound/)  
- бэкенда на Render: `https://bilateralbound.onrender.com`

На странице можно создать сессию (генерируется `sid`), открыть ссылку зрителя и управлять направлением и скоростью движения.

### Быстрые ссылки
- Создать/управлять: [davidbugayov.github.io/bilateralbound](https://davidbugayov.github.io/bilateralbound/)
- **🎯 Тестирование:** `http://localhost:3000/test/test-system.html` (запустите `npm start`)
- Пример короткой ссылки зрителя на бэкенде: `https://bilateralbound.onrender.com/s/<sid>`

### Локальный запуск

Требуется Node.js 18+.

```bash
git clone https://github.com/davidbugayov/bilateralbound.git
cd bilateralbound
npm install
npm start
```

Сервер поднимется на `http://localhost:3000` и будет раздавать статику из `public/`.

При локальной разработке фронтенд использует относительные пути для запросов к бэкенду.

### Как это работает

1. Нажмите «Создать» — фронтенд запросит `sid` у бэкенда (`GET /api/session/new`), сформирует ссылку зрителя и отобразит быстрые элементы управления.
2. Кнопки «↔︎/↕︎/диагональ» устанавливают направление. Ползунок — скорость.
3. «Старт» — подключает вас как контроллера и возобновляет движение (по горизонтали по умолчанию, если направление не выбрано).
4. «Стоп» — ставит на паузу.
5. «Сбросить сессию» — сбрасывает текущую и сразу создаёт новую.

Зритель открывает ссылку вида:
- GitHub Pages: `viewer.html?sid=<sid>&server=https%3A%2F%2Fbilateralbound.onrender.com`
- Короткая на Render: `https://bilateralbound.onrender.com/s/<sid>`

---

### API (бэкенд)

- `GET /api/session/new` — создать сессию, ответ `{ sessionId }`.
- `POST /api/session` — создать сессию, ответ `{ sessionId }`.
- `GET /s/:sessionId` — страница зрителя.
- `GET /` — главная страница с созданием сессии и контроллером.

Сокеты (`socket.io`):
- `join-session` `{ sessionId, role: 'viewer'|'controller' }`
- `control-update` `{ sessionId, input: { dirX, dirY, speedScalar, reset, pause, resume } }`
- Сервер эмитит `ball-state`, `role-update`, `session-expired`, `viewer-joined`, `viewer-left`.

### Тестирование

**⚠️ ВАЖНО:** Каждое изменение в коде должно быть проверено тестами перед коммитом!

#### Запуск тестов

```bash
# Запуск сервера для тестирования
npm start

# Открыть системный тест в браузере
# http://localhost:3000/test/test-system.html
```

#### Доступные тесты

1. **🚀 Полный тест** - комплексная проверка всех функций
2. **🧭 Тест направлений** - проверка всех направлений движения
3. **⚡ Тест движения** - проверка старт/стоп функциональности
4. **🎨 Тест цветов** - проверка изменения цветов и контрастности
5. **📏 Тест масштабирования** - проверка адаптации к разным экранам

#### Что проверяют тесты

##### ✅ Функциональное тестирование
- **Направления движения:** горизонтальное, вертикальное, диагональные
- **Управление движением:** старт, стоп, пауза, сброс позиции
- **Изменение цветов:** фон, мяч, проверка контрастности
- **Масштабирование:** адаптация под разные размеры экрана
- **Синхронизация:** состояние между сервером и клиентом

##### ✅ Интеграционное тестирование
- **WebSocket соединения:** подключение вьювера и контроллера
- **API endpoints:** создание сессии, получение состояния
- **Реальное время:** синхронизация состояния в реальном времени

##### ✅ Регрессионное тестирование
- **Масштабирование радиуса:** мяч не должен сплющиваться
- **Видимость мяча:** цвета должны обеспечивать хорошую видимость
- **Синхронизация состояний:** превью должно соответствовать вьюверу

#### Процесс тестирования изменений

```bash
# 1. Внести изменения в код

# 2. Запустить сервер
npm start

# 3. Открыть тест в браузере
# http://localhost:3000/test/test-system.html

# 4. Запустить релевантные тесты
# - Для изменений в движении: ⚡ Движение
# - Для изменений в цветах: 🎨 Цвета
# - Для изменений в UI: 🚀 Полный тест

# 5. Проверить логи тестов на ошибки
# - ❌ сообщения означают проблемы
# - ⚠️ предупреждения требуют внимания
# - ✅ успешные тесты подтверждают работоспособность

# 6. Только после успешного тестирования:
git add .
git commit -m "Описание изменений + тестирование пройдено"
git push
```

#### Правила коммитов

- **Всегда тестировать перед коммитом**
- **В сообщении коммита указывать:** "тестирование пройдено"
- **При обнаружении ошибок:** исправить код, а не отключать тесты
- **При добавлении новой функциональности:** добавить соответствующие тесты
- **При изменении API:** обновить тесты для проверки новых endpoint'ов
- **При исправлении багов:** добавить регрессионные тесты для предотвращения повторения

#### Отладка при тестировании

- **Тест показывает ошибки:** проверить логи в браузере (F12 → Console)
- **Мяч не двигается:** проверить WebSocket соединение и состояние сессии
- **Цвета не меняются:** проверить синхронизацию между контроллером и сервером
- **Размеры искажены:** проверить масштабирование для разных разрешений экрана

#### Расширение системы тестирования

При добавлении новой функциональности в проект:

1. **Определить тип теста:**
   - **Функциональный тест** - проверка работы новой функции
   - **Интеграционный тест** - проверка взаимодействия компонентов
   - **Регрессионный тест** - предотвращение повторения багов

2. **Добавить тест в `test-system.html`:**
   ```javascript
   async function testNewFeature() {
       log('info', '🆕 Тестирование новой функции...');

       // Отправить команду
       sendCommand({ newFeatureParam: value });

       // Подождать синхронизации
       await new Promise(resolve => setTimeout(resolve, 500));

       // Проверить результат
       const response = await fetch(`/api/session/${sessionId}/state`);
       const state = await response.json();

       // Проверить ожидаемое поведение
       if (условие_успеха) {
           log('success', `✅ Новая функция работает ✓`);
       } else {
           log('error', `❌ Новая функция не работает`);
       }
   }
   ```

3. **Добавить кнопку теста в HTML:**
   ```html
   <button class="test-btn" onclick="testNewFeature()">🆕 Новая функция</button>
   ```

4. **Обновить полный тест:**
   - Добавить вызов нового теста в `runFullTest()`
   - Увеличить счетчик общего количества тестов

#### Что делать если тесты не проходят

1. **Проверить логи тестов** - какие именно ошибки показывают
2. **Найти причину** - ошибка в коде или в тестах
3. **Исправить код** - не отключать тесты!
4. **Перезапустить тесты** - убедиться что исправление работает
5. **Закоммитить исправление** - с сообщением об исправлении

### Отладка

- «Черный экран / Unexpected token '<'» — обычно значит, что вместо JS пришла HTML‑страница (часто 404/redirect). Откройте DevTools → Network, найдите проблемный ресурс, проверьте URL и CORS.
- «Не двигается после Старт» — убедитесь, что вы присоединены как `controller` (нажмите «Старт» ещё раз или выберите направление). В коде предусмотрен автодефолт по горизонтали.
- «Тесты показывают ошибки» — проверьте логи тестов, исправьте код согласно ошибкам, не отключайте тесты.
- Кэш GitHub Pages/CDN может задерживать обновления 1–2 минуты. Сделайте жёсткое обновление: Cmd+Shift+R / Ctrl+F5.
